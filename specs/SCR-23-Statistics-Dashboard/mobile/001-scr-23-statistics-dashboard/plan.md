# Implementation Plan: SCR-23 Statistics Dashboard

**Branch**: `001-scr-23-statistics-dashboard` | **Date**: 2026-09-23 | **Spec**: [spec.md](./spec.md)

## Summary

Implement a read-only Statistics Dashboard as the 6th root tab (`/stats`) that aggregates workout history from Drift into four tiles (Workouts Completed, Total Volume, Total Duration, Avg. Duration) and a per-exercise breakdown list with session counts and best-value highlights. All computation runs in-memory inside a use case on screen entry; no new tables are introduced. The feature follows the clean feature-first architecture with a `features/stats/` directory.

---

## Technical Context

**Language/Version**: Dart 3 / Flutter (stable channel; matches existing project)

**Primary Dependencies**: `flutter_bloc` (Bloc only), `get_it` (DI), `drift` (read-only via existing `WorkoutSessionRepository`)

**Storage**: Drift — read-only via `WorkoutSessionRepository.getAllSessions()`. No new table, no `build_runner` run.

**Testing**: `flutter_test` + `bloc_test`

**Target Platform**: iOS (primary), Android parity; Flutter mobile-app

**Performance Goals**: Stats screen render ≤ 300 ms from tab tap on a 5-year-old mid-range device with ≤ 500 stored sessions (SC-006)

**Constraints**: Offline-only (Drift). No network calls. No new packages. Single fixed dark theme (ADR-037).

**Scale/Scope**: One new screen, one new Bloc, one new use case, two new domain entities. Replaces one `PlaceholderTabScreen`.

## Implementation Phases

### Phase 1 — Setup (prerequisite, no dependencies between items)

- Add `AppColors.successFill` token
- Add 18 `AppStrings.stats*` constants
- Create `stats_data.dart` domain entity
- Create `exercise_stat_row.dart` domain entity

### Phase 2 — Application Layer

- `stats_event.dart` — `StatsLoadRequested`
- `stats_state.dart` — `StatsInitial`, `StatsLoading`, `StatsLoaded`, `StatsError`
- `get_statistics_use_case.dart` — filters valid sessions, computes aggregates + exercise rows
- `stats_bloc.dart` — handles `StatsLoadRequested`; emits Loading → Loaded | Error

### Phase 3 — Presentation Widgets (parallelizable within phase)

- `stats_skeleton.dart` — `StatefulWidget` with `AnimationController` + 4 stat shimmer boxes + 3 row shimmer boxes
- `stat_tile.dart` — value + label + icon; accepts opacity for empty-state dimming
- `stats_empty_state.dart` — dimmed stat grid overlay + empty copy + CTA button
- `stats_error_card.dart` — danger card with title/body/Retry button
- `exercise_stat_card.dart` — type dot + exercise name + session count + best value
- `personal_bests_link_row.dart` — trophy icon with `successFill` wrap + title/sub + chevron

### Phase 4 — Screen Assembly & Route Wiring

- `stats_screen.dart` — `StatefulWidget`; `BlocConsumer`; dispatches `StatsLoadRequested` in `initState`; branches on state to show skeleton/empty/main/error
- `app_routes.dart` — wire `StatsScreen` into Branch 5; add stub for `/stats/personal-bests`
- `get_it_setup.dart` — register `GetStatisticsUseCase` and `StatsBloc`

### Phase 5 — Validation

- `dart format .`
- `flutter analyze` — zero new warnings
- `flutter test` — all existing tests green
- Manual: four UI states (loading → empty → main → error → retry)
