# Implementation Plan: SCR-20 Workout History List

**Branch**: `001-scr-20-workout-history-list` | **Date**: 2026-09-23 | **Spec**: [spec.md](spec.md)

## Summary

SCR-20 is the Workout History screen — a root-level tab that shows the user every completed
workout session in reverse-chronological order, grouped by calendar month. It introduces
`WorkoutHistoryBloc` (inside the existing `workout_session` feature), a
`GetWorkoutHistoryUseCase` that sorts sessions newest-first, and three new presentation
widgets: `HistoryCard`, `HistoryMonthLabel`, and `HistorySkeleton`.

The screen has four live states (Loading/Success/Empty/Error). Error and empty states are
statically distinct sealed variants — they can never be confused by the Bloc (FR-007). Data
is re-fetched on every tab-switch entry via `didChangeDependencies`; back-navigation from
SCR-21 is handled transparently by `StatefulShellRoute` without any re-fetch guard logic.
No new packages. No new tables. No `build_runner` run needed.

**Prerequisites**: SCR-16 must be implemented first — SCR-20 depends on
`WorkoutSession.startedAt` (for display date and month grouping) and `ActualSet.skipped`
(for non-skipped set count). If SCR-20 is implemented before SCR-16, the implementor must
use `completedAt` as a fallback and count all sets, then raise a follow-up to update both
formulas after SCR-16 lands.

## Technical Context

**Language/Version**: Dart 3.x / Flutter 3.x

**Primary Dependencies**: `flutter_bloc`, `go_router`, `get_it`, `equatable`, `fpdart`
(all existing — no new packages)

**Storage**: Drift (existing) — `workout_sessions` table; SCR-20 reads via
`WorkoutSessionRepository.getAllSessions()` only; no writes

**Testing**: `flutter_test`, `bloc_test`, `mocktail` (all existing)

**Target Platform**: iOS + Android (mobile only)

**Project Type**: Flutter mobile app (feature addition)

**Performance Goals**: Loading skeleton appears within one frame of tab activation (SC-003);
Drift read of 100+ sessions completes in < 100 ms on device

**Constraints**: Offline-only (no network); Drift is sole persistence layer; single dark
theme (ADR-037); `Bloc` only (no `Cubit`); `go_router` only; `GetIt` DI; no new packages
(ADR-030); no `intl` package (use pure Dart static arrays for date formatting)

**Scale/Scope**: 1 new screen, 1 new Bloc (3 files), 1 new use-case, 1 new value class,
3 new presentation widgets, 3 amended files (app_strings.dart, app_routes.dart,
get_it_setup.dart), ~6 new AppStrings constants
