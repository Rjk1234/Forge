## Summary

Implement a static local login screen (SCR-03) for ForgeApp. The screen collects email and password, compares them against a hardcoded demo credential using `AppLockCubit`, and on success sets the in-memory app-lock state to unlocked — routing via go_router to SCR-06. No database writes, no network calls, no loading state. Three user stories: happy-path login (P1), wrong-credentials error (P1), and button-disable guard for empty fields (P2).

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| `AppLockCubit` uses Cubit (Principle II.1 requires Bloc with events) | `AppLockCubit` is the established name across all ForgeApp specs, SDS, QA, design, and downstream features (SCR-26). Changing to `AppLockBloc` would require revising all specs without any behavioral benefit. | A proper `AppLockBloc` with `LoginRequested`/`LogoutRequested` events would be constitutionally correct but would force multi-spec revision. The auth flow has exactly two transitions (login, logout) with no complex sequencing — Cubit is appropriate in complexity terms. This is a one-time justified exception; no other Cubits may be introduced. |
