# Implementation Plan: Plan Detail (SCR-10)

**Branch**: `001-plan-detail` | **Date**: 2026-09-19 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/SCR-10-Plan-Detail/mobile/001-plan-detail/spec.md`

## Summary

SCR-10 delivers a read-only Plan Detail screen: the user taps a plan in SCR-08 and sees all exercise targets, then navigates to Edit (SCR-09), Delete (SCR-11), Schedule (SCR-13), or Start Workout (SCR-15). The screen is built on the existing `GetWorkoutPlanByIdUseCase` + `WorkoutPlanRepository` stack — no new data layer work. New components are: `PlanDetailBloc` (Loading / Loaded / NotFound states), `PlanDetailScreen`, `PlanDetailSkeleton`, `PlanExerciseDetailCard` (read-only exercise view), `PlanNotAvailableCard` (error card), and a shared `ShimmerBox` widget extracted from `plans_skeleton_list.dart`.

---

**Language/Version**: Dart 3 / Flutter 3.x (stable)

**Performance Goals**: Plan detail visible within 2 seconds (SC-001); skeleton shown within one frame of screen open

## Component Design

### `ShimmerBox` (shared)

Extracted from the private `_ShimmerBox` in `plans_skeleton_list.dart`. Public widget at `core/widgets/shimmer_box.dart`. Accepts `animation: Animation<double>`, `height`, `borderRadius`, optional `width` or `widthFraction`. Animates between `AppColors.cardAlt` and `Color(0xFF35342F)` using `Color.lerp`.

After extraction, `PlansSkeletonList` uses `ShimmerBox` instead of the private `_ShimmerBox` — identical behaviour, no visual regression.

### `PlanDetailBloc`

```
PlanDetailBloc(
  getWorkoutPlanById: GetWorkoutPlanByIdUseCase,
)

On PlanDetailLoadRequested(planId):
  emit Loading
  result = await getWorkoutPlanById(planId)
  fold: Left  → emit NotFound(message)
        Right → emit Loaded(plan)
```

Single event handler — used for both initial load and re-read after returning from a child screen. The screen dispatches this event on `initState` and again after `await context.push(editRoute)` or `await context.push(deleteRoute)` resolves.

### `PlanDetailScreen`

`StatefulWidget`. `initState` dispatches `PlanDetailLoadRequested`. Uses `BlocBuilder` to switch between skeleton, populated body, and error body.

**Populated body layout (column)**:
1. App bar: back chevron (left) + edit icon + delete icon (right)
2. Title block: plan name (22px/800) + exercise count subtitle
3. Scrollable content: "EXERCISES" section label + `PlanExerciseDetailCard` list
4. Footer: "Schedule" (secondary) + "Start Workout" (primary/lime)

**Populated body navigation** (from screen methods):
- `_onEdit`: `await context.push('/plans/$planId/edit')` → dispatch `PlanDetailLoadRequested`
- `_onDelete`: `await context.push('/plans/$planId/delete')` → dispatch `PlanDetailLoadRequested`
- `_onStartWorkout`: `context.push('/plans/$planId/start')`
- `_onSchedule`: `context.push('/plans/$planId/schedule')`
- `_onBack`: `context.pop()`

**"Start Workout" disabled condition**: `plan.exercises.isEmpty`

### `PlanExerciseDetailCard`

`StatelessWidget`. Takes `PlanExercise`. Renders:
- Header: type dot (7×7 circle) + type label + exercise name
- Body: `_PlanFieldGrid` — layout varies by `exercise.type`

`_PlanFieldGrid` uses `_PlanFieldBox` (read-only value + label cell):
- Weighted: 3-column row (Sets, Reps, Weight) + 1-column row (Rest)
- TimeBased: 3-column single row (Sets, Duration, Rest)
- Bodyweight: 3-column single row (Sets, Reps, Rest)

### `PlanDetailSkeleton`

`StatefulWidget` that owns its `AnimationController` (300ms repeating). Creates and disposes the controller. Renders:
- App bar: live back chevron + two skeleton icon boxes
- Two shimmer title lines (70% width + 35% width)
- Three shimmer exercise cards (each with two shimmer lines)
- Two shimmer footer buttons

### `PlanNotAvailableCard`

`StatelessWidget`. Renders the danger error card (X-in-circle icon + title + body + "Back to Plans" button). Takes `onBackToPlans: VoidCallback`.
