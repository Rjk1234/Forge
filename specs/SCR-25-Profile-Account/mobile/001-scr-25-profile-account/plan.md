**Branch**: `001-scr-25-profile-account` | **Date**: 2026-09-24 | **Spec**: [spec.md](spec.md)

## Summary

SCR-25 is the Profile / Account screen — the first form screen in ForgeApp. It allows the user to view and edit four profile fields (display name, fitness goal, experience level, height/weight) stored in the existing `user_profiles` table, and navigate to the logout confirmation screen. The implementation builds a complete Clean Architecture layer on top of an already-existing `UserProfileRecord` and `ProfileLocalDataSource` stub, introduces the first full form pattern (text inputs, segmented control, dropdown-style picker, validation), and delivers a new success toast widget with two new AppColors tokens.

---

## Technical Context

**Language/Version**: Dart (latest stable via FVM); Flutter latest stable  
**Primary Dependencies**: `flutter_bloc` (Bloc only), `get_it`, `go_router`, `drift`, `fpdart` (`Either`) — all from governed set (ADR-030)  
**Storage**: Drift — `user_profiles` table, single row at id `kProfileKey = 0`  
**Testing**: `flutter_test`, `bloc_test`, `mocktail` — from governed set  
**Target Platform**: Android API 29+ and iOS 15+ (phone portrait)  
**Project Type**: Flutter mobile app — Clean Feature-First Architecture  
**Performance Goals**: Drift read + form render within single frame after skeleton; local-only, no network latency  
**Constraints**: Fully offline; no new packages; single dark theme; all strings via `AppStrings`; all colors via `AppColors`  
**Scale/Scope**: Single user, single profile record; 1 new feature directory, 11 new files, ~5 modified shared files

## Key Design Decisions (Summary — Full Detail in research.md)

| ID | Decision | File |
|----|----------|------|
| D-01 | Route at `/profile` via `context.push` from `HomeHeader` | `app_routes.dart`, `home_header.dart` |
| D-02 | `registerFactory<ProfileBloc>` — fresh instance per push | `get_it_setup.dart` |
| D-03 | `UserProfile` is pure Dart with `String` fields (not enums) | `user_profile.dart` |
| D-04 | `UserProfileMapper` bridges Drift↔domain | `user_profile_mapper.dart` |
| D-05 | `ProfileRepository.getProfile()` returns `UserProfile?`; null = first-time | `profile_repository.dart` |
| D-06 | `GetProfileUseCase` applies first-time defaults on null | `get_profile_use_case.dart` |
| D-07 | 6 Bloc states; no `ProfileSaveSuccess` state; toast is local screen state | `profile_state.dart` |
| D-08 | Toast driven by `BlocListener` detecting `ProfileSaving → ProfileLoaded` | `profile_screen.dart` |
| D-09 | Empty height/weight = allowed (0.0 stored); non-empty invalid = blocked | `profile_screen.dart` |
| D-10 | `ProfileSkeleton` is a `StatefulWidget` owning `AnimationController` | `profile_skeleton.dart` |
| D-11 | Feature-specific `ProfileErrorCard` (ElevatedButton lime); not core `ErrorCard` | `profile_error_card.dart` |
| D-12 | 23 new `AppStrings.profile*` constants | `app_strings.dart` |
| D-13 | Two new AppColors: `successFill`, `successBorder` | `app_colors.dart` |
| D-14 | Profile entry from `HomeHeader` via `context.push('/profile')` | `home_header.dart` |
| D-15 | Fitness goal picker: `showModalBottomSheet` with 3 `ListTile` options | `profile_screen.dart` |
